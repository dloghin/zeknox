# Task 03: Goldilocks Quadratic Extension Field (gl64_ext2_t)

## Objective

Create a CUDA-compatible Goldilocks quadratic extension field type `gl64_ext2_t` that specializes the generic `ExtensionField` template from `native/primitives/extension_field.cuh` for the Plonky2 Goldilocks extension `GF(p^2)` where `p = 2^64 - 2^32 + 1` and the irreducible polynomial is `x^2 - 7`.

## Background

Plonky2 uses the quadratic extension `F_{p^2}` with:
- Base field: Goldilocks (`p = 0xFFFFFFFF00000001`)
- Extension polynomial: `x^2 - W` where `W = 7`
- Elements: `a + b*x` where `a, b` are Goldilocks elements
- Multiplication: `(a + bx)(c + dx) = (ac + 7bd) + (ad + bc)x`

This is used extensively in:
- FRI protocol (folding uses extension field challenges)
- Opening proofs (evaluation at extension field points zeta, g*zeta)
- `prove_openings` composition polynomial

    static __host__ __device__ gl64_ext2_t one();

    // Arithmetic

    friend __host__ __device__ gl64_ext2_t operator-(gl64_ext2_t a, const gl64_ext2_t& b);
    friend __host__ __device__ gl64_ext2_t operator*(const gl64_ext2_t& a, const gl64_ext2_t& b);

    // Negation
    static __host__ __device__ gl64_ext2_t neg(const gl64_ext2_t& a);

    // Inverse
    static __host__ __device__ gl64_ext2_t inverse(const gl64_ext2_t& a);

    // Exponentiation

## Implementation Details

### Multiplication
```
(a + bx)(c + dx) = ac + adx + bcx + bdx^2
                  = ac + 7*bd + (ad + bc)x
```
Since `x^2 = 7` (W = 7, non-negative), the formula is:
- `result.real = a*c + 7*b*d`
- `result.imag = a*d + b*c`

### Inverse
```
(a + bx)^{-1} = (a - bx) / (a^2 - 7*b^2)
```
- Conjugate: `(a, -b)`
- Norm: `a^2 - 7*b^2` (a Goldilocks element)
- Result: `conjugate * norm_inv`

### Primitive Root of Unity

For the Plonky2 extension field, the primitive root is:
- `TWO_ADIC_SUBGROUP_GENERATOR = (18081566051660590251, 16121475356294670766)` (from `plonky2/field/src/extension/quadratic.rs`)

Use `pow()` to derive roots of unity for smaller subgroups.

## Existing Code to Reuse

- `native/ff/gl64_t.cuh`: Base field type with all arithmetic
- `native/primitives/extension_field.cuh`: Generic template (may be usable if we define a CONFIG, but gl64_t doesn't use the Field<CONFIG> pattern -- a direct implementation is cleaner)
- `plonky2/field/src/extension/quadratic.rs`: Reference for constants and arithmetic

## Compatibility Note

The existing `extension_field.cuh` uses the `Field<CONFIG>` template which is designed for Montgomery-form fields (BN254, etc.). The Goldilocks `gl64_t` uses a different representation (not Montgomery on device). Therefore, a **direct implementation** of `gl64_ext2_t` using `gl64_t` directly is recommended rather than trying to fit it into the `ExtensionField<CONFIG>` template.
